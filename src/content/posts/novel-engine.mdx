## 概要

ノベルゲームの画面で、クリックするとテキストが進み、それに合わせて背景や立ち絵が変わる仕組み。作品を作るたびに作り直していて、現在の版は[氷途のリポジトリ](https://github.com/coiluck/project-glacia/tree/main/src/features/scenario)にある。

2026/03 の版で戻るボタンを付けたところ、戻ってもテキストしか戻らないことがテストプレイで分かった。直すにはエンジンの中心部分を作り直す必要があったのでその作品では修正を見送り、次の作品（現在の版）で作り直した。このページではその経緯を順に書く。

<Video src="/videos/glacia-scenario.mp4" poster="/videos/glacia-scenario.jpg">現在のエンジンで動かしている画面</Video>

| 機能 | 内容 |
| --- | --- |
| 演出 | 背景・立ち絵の切り替え、背景を動かす、待つ |
| 分岐 | 選択肢でシナリオが分かれる。分岐の中でさらに分岐できる |
| 条件 | 選択肢で好感度などの値を増やし、その値で選択肢の表示を変える |
| 戻る・ログ | 1つ前の地点に戻る。読んだテキストを一覧で見る |
| セーブ・ロード | その地点の状態を保存し、そこから再開する |

## 分岐の中の分岐

2025/09 の版では本編から分岐して本編に戻ることはできたが、分岐の中でさらに分岐することはできなかった。2026/03 の版では、次のような分岐を書けるようにした。

<Mermaid code={`
flowchart LR
  m1[本編] --> c1{選択肢1}
  c1 -->|A| a[a-1 → a-2]
  c1 -->|B| b1[b-1] --> b2[b-2] --> c2{選択肢2}
  c2 -->|W| w[w-1 → w-2]
  c2 -->|X| x[x-1 → x-2]
  w --> b3[b-3]
  x --> b3[b-3]
  a --> m2[本編の続き]
  b3 --> m2
`} />

分岐の状態はスタック（後から積んだものを先に取り出す配列）で持った。分岐に入るときに「どの分岐の何行目にいるか」を積み、分岐を読み終えたら取り出して、親の分岐の続きに戻る。以下ではこれを分岐スタックと呼ぶ。

## 戻るボタン

同じ 2026/03 の版でテキスト欄の近くに戻るボタンを付けた。Keyやゆずソフトの作品には戻るボタンがありノベルゲームにはあるのが普通だと思っていたので、深く検討せずに付けることにした。実装してみると問題が2つあった。

### 1つ前の地点が分からない

<Mermaid code={`
flowchart LR
  c1{選択肢1} -->|B| b1
  subgraph B[分岐 B]
    b1[b-1] --> b2[b-2] --> c2{選択肢2}
    subgraph W[分岐 W]
      w1[w-1] --> w2[w-2]
    end
    c2 -->|W| w1
    w2 --> b3[b-3]
  end
`} />

分岐スタックは「今どこにいるか」しか持っていない。上の図で B → W を選び、W を読み終えて b-3 に戻ってきたとき、分岐スタックには B の b-3 しかなく、直前に W を通ったことは分からない。

そこで、分岐スタックとは別に、表示した地点を履歴として積み、戻るときは履歴を後ろから取り出して復元することにした。履歴の各地点には、その時点の分岐スタックの写しも入れる。当時のブログにも「多少無理やり」と書いた方法だが、入り組んだ分岐の中でも1つ前の地点に戻れるようにはなった。

### 好感度を何度も増やせる

選択肢で好感度を増やす場合、選択肢より前に戻れると、同じ選択肢を何度も選んで好感度をいくらでも増やせてしまう。

ここは選択肢を選ぶと履歴をリセットすることで、選択肢より前には戻れない仕様にした。エンジンを大きく変えずに問題を避けられる妥当な方法だと考えた。

ただ、そのために「選択肢より前には戻れません」とゲーム内に表示することになった。ゲームの内容と関係のない文をプレイヤーに見せるのは嫌ではあった。

## テストプレイで見つかった問題

テストプレイ中に、戻ってもテキストしか戻らないことに気づいた。b-3 で背景を変えていた場合、w-2 に戻るとテキストは w-2 になるが、背景は b-3 のままになる。立ち絵も同じだった。

原因はすぐに分かった。背景や立ち絵の変更を「その行で実行する処理」として持っていたため、履歴には「どの行にいるか」しか残らず、その地点で背景が何だったかという情報がどこにもない。

直すには、各地点で画面がどういう状態かをすべて記録しておき、戻るときはそれを丸ごと復元する必要がある。これはエンジンの中心部分の作り直しになり、シナリオを書く Markdown と、それをシナリオのデータに変換するスクリプトにも手を入れることになる。

修正はこの作品では見送り、次の作品で作り直すことにした

作りたいものはまだいくらでもあり、1つの作品の修正に時間をかけるより先に進みたかった。友人に遊んでもらって感想をもらうのが制作の励みになっているので、早く遊んでもらいたかったのもある。

## 現在の版での作り直し

次の作品で前の節の考えどおりに作り直した。さらに、今まで HTML を直接操作する JavaScript 関数として使っていたが、エンジン内部に `HTMLElement` の id などが侵食している状態が不満であったため、なるべく純粋関数に閉じ込めて、その他も画面の処理と分けて書くようにした。

### 命令をデータにして2種類に分けた

演出を関数ではなくデータで書くようにした。関数では、保存するときに `JSON.stringify()` をすると復元できないからだ。シナリオの1行は次のように書く。

```ts
{
  text: '港に着いた。',
  speaker: 'キャラA',
  commands: [
    { type: 'bg', file: 'ice_port.avif', transition: 'crossfade' }, // 状態を変える命令
    { type: 'bgMove', direction: 'leftToRight', duration: 5000 },   // その場の演出
  ],
}
```

そのうえで命令を次の2種類に分けた。

| 種類 | 命令 | 戻ったとき |
| --- | --- | --- |
| 状態を変える命令 | 背景、立ち絵の表示・削除 | その地点の状態に戻る |
| その場の演出 | 背景を動かす、待つ | 保存していないので再生しない |

状態を変える命令は、「今の場面の状態」と「次の行」から「次の場面の状態」を作る純粋関数で適用する。結果は場面の状態（背景・立ち絵・テキスト・話者）というデータとして手元に残るので、各地点の状態をそのまま記録できる。

```ts
// 現在の状態とシナリオの 1行を受け取って更新後の状態を返す
function reduceLine(snapshot: SceneSnapshot, line: ScenarioLine): SceneSnapshot
```

### 地点ごとに状態を丸ごと記録する

1行進むたび、選択肢を選ぶたびに、そのときのゲームの状態を丸ごと履歴に積む（最大50件）。状態には次のものが入っている。

- 進行位置（シナリオと行、分岐スタック）
- 場面の状態
- 好感度などの値

戻るときは、履歴から取り出した状態で置き換えるだけで済む。好感度も一緒に戻るので、選択肢より前に戻れない制限をなくし、「選択肢より前には戻れません」の表示も出さなくてよくなった。セーブも同じ状態を保存し、ロードはそれで置き換える。ログは履歴に入っている場面の状態を並べて表示している。

| | 2026/03 の版 | 現在の版 |
| --- | --- | --- |
| 履歴に残すもの | 行の位置と分岐スタック | ゲームの状態すべて |
| 戻ったときの背景・立ち絵 | ✕ 先の場面のまま | ✓ その地点の状態に戻る |
| 選択肢より前に戻る | ✕ できない（好感度の二重加算を防ぐため） | ✓ できる（好感度も一緒に戻る） |

### 何もない画面まで戻れた不具合

作り直した後最初の行で戻るを押すと、テキストも背景もない画面に戻ってしまう不具合があった。1行進む直前の状態を履歴に積む作りにしていたので、最初の行を表示する前のまだ何も表示していない状態まで履歴に入っていた。最初の1回だけは履歴に積まないようにして直した。

### 画面との分け方

<Mermaid code={`
flowchart LR
  P[プレイヤー] -->|クリック・選択・戻る| E[エンジン<br>React に依存しない]
  E -->|場面の状態| S[zustand]
  S --> V[画面]
  E -->|その場の演出| V
`} />

エンジンは React を使わずに書き、画面には場面の状態を zustand 経由で渡すだけにした。画面側は、渡された状態を描画することと、演出を再生することしかしない。
